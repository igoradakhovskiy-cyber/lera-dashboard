# Lera Rumaa — рекламный дашборд

Интерактивный отчёт по рекламе Meta (Facebook / Instagram) для кабинета
**lera rumaa 1** (`act_834243695642037`, USD, Europe/Kiev). Данные тянутся через Meta
Marketing API, шифруются паролем и показываются статичной страницей.

Собран из шаблона `~/nite-dashboard` (родня: Lagoon, Desa, Next). От них отличается
тремя вещами:

1. **Главный фильтр — запуск, а не язык.** Язык тут один.
2. **Лид = подписка (Subscribe)**, а не `lead`.
3. **Плана нет**, только факт. **CRM нет**: в объявлениях нет UTM-меток.

## Что внутри
- **Фильтр по запуску** (первый в шапке): «Все запуски» + кнопка на каждый продукт.
  При выборе запуска период прыгает на весь его срок. Выбор запоминается в браузере.
- **Периоды:** Сегодня · 7 / 14 / 30 дней · Текущий месяц · Всё время (при выбранном
  запуске «Весь запуск»). Считаются от сегодняшней даты по времени кабинета (Киев), как в
  Ads Manager, поэтому «Сегодня» на паузе честно показывает ноль. Начало периода не
  уходит раньше старта выбранного запуска.
- KPI: расход (и в среднем за день), подписки, CPL, конверсия клик → подписка; показы,
  клики, CTR, CPM, CPC.
- **Сравнение запусков**: появляется само, когда в периоде есть два и больше продукта.
- Динамика по дням, воронка показы → клики → подписки.
- **География**: расход / подписки / CPL / CTR по странам, фактические данные из
  `breakdowns=country`, а не пропорциональная раскидка.
- Кампании → адсеты → объявления (дрилл-даун), плейсменты, галерея креативов с живым
  превью Meta.

## Запуски: откуда берутся
Запуск читается из **имени кампании**, отдельной настройки для него нет:

```
019_UA_rebuild_AQ_[CPL]_CBO_17.09.2026        → rebuild
020_PL_DE_ES_rebuild_AQ_[CPL]_CBO_17.09.2026  → rebuild   (гео из нескольких токенов)
002_WW_7_steps_AQ_[CPA]_CBO_18.02.2026        → 7_steps   (запуск из двух токенов)
```

Правило: после номера идут гео-коды ЗАГЛАВНЫМИ (`UA`, `EU`, `PL_DE_ES`, `WW`), затем
название запуска **строчными**, затем этап (`AQ`/`RET`/…), `[KPI]`, `ABO`/`CBO`, дата.
Новый продукт достаточно назвать по этой схеме, и на следующей сборке он появится
в фильтре. Красивое имя для кнопки задаётся в `LAUNCH_LABELS`
(`scripts/fetch-meta.mjs`), иначе оно собирается из токена: `7_steps` → «7 steps».

Одинаковые имена объявлений (`001`, `002_give_us`) в разных запусках — разные креативы,
поэтому в галерее они группируются по паре «запуск + имя».

## Лид и окно
- `MIN_DATE = 2026-09-17`: старт Rebuild на новом пикселе «Lera Rumaa_sep». До этого
  кабинет оптимизировался на другие события (Lead / Purchase на старом пикселе).
  Смешивать их с подписками нельзя: цена результата потеряет смысл.
- `LEAD_TYPE = subscribe_total`. Meta отдаёт Subscribe в поле **`conversions`**, а в
  `actions` он виден только как безымянный `fb_pixel_custom`. Сверка за 17–25.09:
  `subscribe_total` 2373 = «Результаты» в Ads Manager, CPL $1,02.
- **Ограничение:** событие результата одно на весь дашборд. Если следующий продукт будет
  оптимизироваться на другое событие (например, Lead), он покажет 0 подписок. Тогда
  нужен свой тип результата на каждый запуск.

## Проверка целостности
Расход по плейсментам и по странам сверяется с расходом аккаунта. Расхождение больше 1%
валит сборку: значит, breakdown-проход недобрал строк.

## Локально
```bash
npm install
DASHBOARD_PASSWORD='<пароль>' npm run data   # Meta → .data/latest.json → public/data/latest.enc
npm run dev                                   # http://localhost:4614/lera-dashboard/
```
Токен Meta берётся из `~/.config/claude-meta/token.env` или из `META_ACCESS_TOKEN`.

## Деплой (ещё не делался)
Как у остальных дашбордов: GitHub Pages + крон каждые 3 часа.
1. Репозиторий **`lera-dashboard`**: имя обязано совпадать с `base` в `vite.config.ts`.
2. `gh api -X POST repos/<user>/lera-dashboard/pages -f build_type=workflow`
3. Secrets: `META_ACCESS_TOKEN`, `DASHBOARD_PASSWORD`; variable `META_ACCOUNT_ID` =
   `act_834243695642037`.
4. `git push`: workflow соберёт и опубликует, дальше пересборка каждые 3 часа.
   На странице по `?admin` появляется кнопка «↻ Обновить».

## CRM
Сейчас подключить нельзя: у объявлений пустые `url_tags`, и строку CRM не к чему
привязать. Чтобы появились квалы/CPQL, сначала нужны UTM в объявлениях:
`utm_campaign={{campaign.name}}&utm_content={{ad.name}}` (лучше ещё
`utm_id={{campaign.id}}&utm_term={{adset.id}}`, как в Lagoon). Дальше по рунбуку
`docs/REPLICATE.md`, раздел «CRM-слой».
